# Два пода по 2 H100 и восстановление очередей

2026-10-06. Активные exp11, exp12 и 4B-бенчмарки продолжаются в старых подах. Новые манифесты имеют `replicas: 0`.

## Решение

`infra/exp-vm-a.yaml` и `infra/exp-vm-b.yaml`: два StatefulSet, по 2 H100, 54 CPU, 244 GiB RAM и 64 GiB `/dev/shm`. A использует существующий PVC, B отдельный `vcharkin-parallel-r1-b-pvc` на 200 GiB. Общая обязательная anti-affinity по hostname размещает их на разных узлах. Если второй узел недоступен, B остаётся Pending; совместное размещение не считается изоляцией.

Общий RWO PVC разрешает несколько подов только на одном узле. Поэтому разделение без второго тома защищает лишь от сбоя пода. Проверено на текущем кластере: основной и extra-под находятся на node803, один PVC; CSI provisioner `io.openebs.csi-mayastor`. Читать PV на уровне кластера нельзя по RBAC. Поддержка клонирования не проверена. Для подготовки B используем CPU Job после окончания текущих задач и открепления исходного PVC. Попытка совместного размещения получила InterPodAffinity/VolumeBinding (volume node affinity conflict), в том числе с GPU-toleration. Копирование не началось; ожидающий Job удалён.

Источник: [режимы доступа Kubernetes](https://kubernetes.io/docs/concepts/storage/persistent-volumes/#access-modes), [anti-affinity](https://kubernetes.io/docs/concepts/scheduling-eviction/assign-pod-node/#affinity-and-anti-affinity).

## Что исправлено

- Команда остаётся в голове очереди до завершения. После потери пода выполняется повтор.
- `flock` разрешает один runner на GPU; дочерние процессы наследуют блокировку. Для добавления команды применяется `scripts/enqueue.sh`, а не `echo >>`. Он защищает запись от потери при замене файла очереди.
- Код выхода сохраняется до подстановки `date`. Старое `echo "$(date) ... $?"` могло записывать 0 после ошибки, что воспроизведено в bash.
- Обычная ошибка сохраняет команду в `gpuN.txt.failed` и позволяет следующей задаче стартовать. После трёх прерываний подряд команда также сохраняется туда, exit=125. Лимит задаётся `MAX_ATTEMPTS`.
- Новый entrypoint запускает очереди после перезапуска контейнера. Завершение одного runner приводит к перезапуску пода; соседняя задача в этом поде тоже прерывается. Второй StatefulSet продолжает работу.
- `start_experiment.sh` сохраняет исходный коммит, запрещает подмену/грязную рабочую копию и повторный launcher одного запуска. Передавать SHA при постановке в очередь: имя ветки разрешается только при первом старте.
- Общий безопасный `run_experiment.sh` запускает SFT/eval из закреплённой ветки через `EXPERIMENT_REPO`. Поэтому сохранение прерванных чекпоинтов работает и для старых экспериментальных веток.
- Старые чекпоинты и train.log уходят в `runs/<name>/interrupted/<time>/`. SFT начинается заново: состояние optimizer, scheduler и RNG авторский тренер не сохраняет. Это сохранение артефактов, не точное продолжение обучения.
- Маркеры SFT/eval и JSON `score.py` записываются через временный файл и rename. Генерации остаются доступны для повторного подсчёта.

Повторы имеют семантику «как минимум один раз». Если процесс потерян после завершения задачи, но до удаления строки, она повторится; задачи должны сохранять этапы и пропускать завершённые. Для произвольной команды с внешними побочными эффектами очередь не даёт exactly-once. Блокировка не предназначена для двух подов, одновременно пишущих на один PVC.

## Переход

1. Доставить ветку инфраструктуры бандлом в `/work/parallel-r1`, создать detached worktree `/work/runner-src`. Этот код управляет очередями; код модели остаётся в отдельных ветках.
2. Создать отдельный PVC B и оба новых StatefulSet с replicas=0. CPU Job пока не применять: текущее размещение не позволяет совместить его с исходным GPU-подом.
3. Дождаться всех текущих задач и собрать результаты, включая exp11/12, greedy IFEval и 16k. Проверить не только пустые очереди, но и процессы/START без END: старый runner уже убрал выполняемую строку.
4. Удалить завершившийся extra-под по передаче. Масштабировать старый основной StatefulSet в 0; дождаться прекращения процессов и открепления PVC. Данные и старый StatefulSet сохранить.
5. Применить `infra/copy-workspace-b.yaml`. Job монтирует исходный том read-only и новый том в `/work`, копирует assets, venv и bench_data, создаёт рабочие копии закреплённых Git-коммитов. Активные очереди, runs и поколения не копируются. Не обновлять входы во время копирования. Дождаться успешного Job и COPY_READY, сохранить лог, затем удалить завершённый Job для открепления обоих PVC. Очереди GPU0/1 старого PVC должны быть пусты. Доставить необходимые экспериментальные ветки на оба тома.
6. Масштабировать A и B в 1. Проверить разные hostname, по 2 H100, наличие runner0/1, `/work` и очередей. При задержке Multi-Attach дождаться открепления, не удалять PVC.
7. Новые команды добавлять через `enqueue.sh`, указывая закреплённый коммит:
   ```bash
   bash /work/runner-src/scripts/enqueue.sh 0 'bash /work/runner-src/scripts/start_experiment.sh <commit> <name> <overrides>'
   ```

Сравниваемые запуски хранить на одном PVC или переносить их генерации для `paired_compare.py`. Итоговые таблицы собирать с обоих подов. Распределение по узлам не защищает от отказа общего хранилища, namespace или общего механизма preemption. Автоматика простоя может масштабировать оба пода в 0; после разрешённого scale-up очереди стартуют сами. Архивы прерванных запусков занимают диск; удалять их после сохранения нужных результатов.

## Проверка

Девять CPU-проверок на собственном GPU-поде, без обращения к GPU: прерывание и повтор, ограничение повторов, два runner, ошибка задачи, конкурентное добавление, пустая строка, отказ supervisor, закрепление кода старой ветки, отсутствие маркера после частичного отчёта. Новый `score.py` пересчитал завершённый ARC-C (1172 задачи), метрики совпали. `bash -n`, `git diff --check`, server dry-run манифестов прошли. GPU-переход пока не выполнен. A/B созданы с replicas=0, PVC B ожидает потребителя. Исправленный CPU Job применяется после освобождения исходного тома.
