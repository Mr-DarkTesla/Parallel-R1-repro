# Оценка Qwen3-4B на MATH500 и AIME 2024/2025/2026 (32k)

Код, которым получены точки графиков [benchmark-trajectories](../benchmark-trajectories-2026-10-14/README.md)
и сравнение «две случайные ветки». Снимок рабочих каталогов 13–15 октября 2026 **в том виде, в каком
они запускались**: абсолютные пути заменены на `${PROJECT_ROOT}` (корень проекта на общей NFS) и
`${HOME}`, остальное не менялось. Это не переносимый пакет: скрипты ссылаются на соседние каталоги
`work/experiments/` (модели, вопросы, scorer, окружение), которые восстанавливает
[бандл 4B](../4b-2026-10-14/README.md). Скрипты отправки задач на GPU-кластер сюда не включены: запуск
на своём железе — `launch_node.py` / `controller.py` на каждом узле.

## Протокол

590 задач: MATH500 (500) + AIME 2024/2025/2026 (по 30), один ответ на задачу, temperature 1, top_p 1,
контекст 40960. Корректность — замороженный Math-Verify 0.8.0 по ответу после `</think>`.
$F$ — физические вызовы `model.forward` при генерации: в native-оценке считаются хуком на модели vLLM
(`counting_worker.py`), в структурной — ledger'ом движка, который обязан совпасть с физическим счётчиком.

## Что каким каталогом посчитано

| Каталог | Модели | Бюджет ответа / ветки | Движок |
|---|---|---|---|
| `eval-baselines-32k-20261013` | Qwen3-4B Instruct (native thinking), Full SFT | 32768 / 768 у SFT | Instruct — обычный vLLM (`native_worker.py`), SFT — структурный движок по шаблону rolling-оценки; очередь на тех же 32 GPU |
| `eval-rl300-vllm-rolling-32k-20261013` | R2 RL300 | 32768 / 768 | структурный DAG-движок на vLLM BF16, rolling-декодер, 4 задачи на GPU; часть ответов досчитана из FP32-прогона |
| `eval-intermediates-vllm-rolling-32k-20261013` | R2 RL50…RL250 | 32768 / 768 | та же очередь с шаблонами rolling-оценки |
| `rl-r4-posteval-20261013` | R4 RL50/100/150 (новая награда) | 32000 / 4000 | копия rolling-движка, 16 GPU |
| `eval-rl300-random2-8gpu-20261014` | R2 RL300 | 32000 / 4000 | движок R4 + `branch_selection.py`: из N объявленных моделью веток исполняются 2 случайные |

`engine/` — тот же структурный движок, что и в RL-обучении
(`../4b-2026-10-14/snapshot/work/experiments/rl-r4-dapo2k-sft-16gpu-20261013/src`), плюс
`rolling_decoder.py`; отличия в нескольких файлах касаются только режима оценки.

Последовательность запуска одной оценки: `prepare.py` (копирует движок, собирает `job.json` и seal хешей) →
`launch_node.py` / `controller.py` на каждом узле → `worker.py` на каждом GPU → `finalize.py` (сводит
`result.json`). Для random2 `prepare.py` патчит `rollout.py`: сохраняется исходный бюджет на ветку,
заголовки `<Path>k` оставляют исходные номера, выбор детерминирован seed'ом задачи.

`eval-rl300-random2-8gpu-20261014/result.json` — итоговый результат random2; остальные результаты
в компактном виде лежат в `../benchmark-trajectories-2026-10-14/*.json`.

## Ограничения

- Протоколы не полностью совпадают: RL300 и промежуточные шаги — 32768/768, R4 и random2 — 32000/4000;
  в RL300 часть ответов FP32, остальное BF16.
- Повторный запуск требует того же дерева `work/experiments` и GPU A100 80 GB; здесь он не проверялся.
