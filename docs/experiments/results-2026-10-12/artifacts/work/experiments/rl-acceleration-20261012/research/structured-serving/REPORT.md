# Structured Qwen3-4B serving feasibility, 2026-10-12

Recommendation: build the structured rollout adapter on **SGLang v0.5.21 + FlashInfer**, with a small internal fork/merge KV-handle and position patch. This is the most direct viable engine architecture found, **not a measured fastest engine**, and not a drop-in replacement through the ordinary generate API. vLLM can also implement it, but its normal position buffer simultaneously participates in physical KV-slot addressing, making the patch broader. Keep the current validated HF decoder as the control until actual 4B checkpoint/precision parity passes.

No GPU was allocated, accessed, launched, or stopped. No production input was modified. An actual tiny-Qwen3 CPU FP64 proof was run on the authorized existing Python environment with `CUDA_VISIBLE_DEVICES=""`; upstream source retrieval and CPU work were read-only except isolated research artifacts.

## Exact existing semantics and the equivalence boundary

The canonical source is `experiments/parallel_instruct/source/parallel_structure.py`, SHA-256 `f9b26772090c5d8af0bff54f26369da5e26f850e79d9261b6f0da5531000881f`.

- `layout`, lines 37–46: `<Parallel>`, sampled count and newline are shared; every path starts at the same semantic position; the merged suffix starts at shared-base plus **maximum path-span length**, including path header and closure. Physical assembled length is larger than semantic position after a fork.
- `attention`, lines 53–59: ordinary lower-triangular attention except later sibling path queries cannot read earlier sibling spans. Any inter-path whitespace is owned by the preceding path (lines 42–44), closing an indirect multilayer leakage route. Tokens at and after `</Parallel>` see every path.
- `rollout.py`, lines 95–119: all siblings have the same shared prefix, distinct path header, independent per-call seed, and one physical batched-forward ledger. Widths up to eight already run together; an engine does not gain another factor of eight by rediscovering this batching.
- `rollout.py`, lines 122–143: sampled raw EOS or structural stops may be replaced by visible `</Path>` / `</Summary>` with identical action-span length. Raw sampled ID remains the loss/logprob target. Forced headers/bridges have response mask zero; sampled terminal actions have mask one.
- `structured_replay.py`, `call_inputs` / `score_call`: the scored prefix is the actual per-call prefix, not an assembled-response slice. Positions and mask are canonical. Guarded logits are normalized after temperature and blocked-token masking.

**Yes, exact independent-path serving is possible, with important conditions:** prefill the shared prefix under its already-correct structure; fork the prefix KV; compute each branch with only that prefix and its own private KV using the same semantic positions; merge the shared prefix **once** and branch-private KV in canonical order; prefill only canonical closures/bridge/suffix against that union with the correct explicit positions. At every layer the branch hidden states, RoPE keys, and values equal their corresponding structured-mask states. The merged query sees the same ordered KV multiset. Induction over layers and successive fork/merge rounds establishes equality for a decoder-only Qwen3 with per-token norms/MLPs and no extra sequence-global operation.

**No, independently generated paths followed by a normal causal prefill of their concatenated text are not equivalent.** Later paths get hidden states informed by earlier paths, and normal positions are wrong. Setting repeated positions alone does not restore sibling isolation. The first path of the first fork can happen to match; post-merge and later-fork behavior do not inherit that guarantee.

**No, concatenating complete per-branch caches is not correct.** It repeats the shared prefix and changes attention normalization. Union only branch-private tails plus one shared prefix. KV is already RoPE-rotated at the original semantic positions; do not rotate it again at physical assembled offsets.

**Terminal handling matters.** The current HF decoder stops before feeding its final sampled action into KV. A cache-exporting engine must materialize the *visible canonical* closing token before merge. If an engine has already written a raw EOS key, remove that tail before writing canonical `</Path>`; never reuse EOS KV as `</Path>` KV. The sampled EOS remains the original loss target. Forced closure writes generate no sampled action but consume real engine work. Summary and next-main phases similarly require canonical visible summary closure.

## What the engines support, and what needs a patch

| Capability | Official support found | Required structured work |
| --- | --- | --- |
| Continuous batching / scheduler overlap | SGLang scheduler merges active/new requests; vLLM V1 scheduler schedules token work | Admit ready path/main/summary requests by dependencies; preserve independent RNG and episode identity |
| Prefix KV reuse | SGLang RadixCache; vLLM automatic prefix cache | Structured KV handles, semantic-position/layout cache identity, stable actor version; cache hit cannot mean zero attributed work |
| RoPE positions inside runner | Both Qwen3 model implementations accept position tensors | Carry explicit semantic positions through request/forward-batch/decode; physical KV offsets must stay separate |
| Generic user-supplied 4D self-attention mask | Not exposed in the audited ordinary generate schemas | Either structured prefill metadata/backend patch, or the proved causal-segment KV composition |
| Request KV union/merge | No ordinary generate API found | Retained shared/private KV ownership, merge row mapping, cancellation/eviction safety |
| CUDA graph decode | Both engines have graph runners | Verify patched positions/index buffers remain graph-safe; dynamic data can change inside fixed-shape buffers |
| BF16 serving | Qwen3 model path and FlashInfer BF16 interfaces exist | Pin actual runtime/dependency build; measure checkpoint parity; no speed claim from source support |
| Weight refresh | SGLang update-weights APIs and cache flush | Whole-episode/group actor lease; no hot swap during any phase or resident structured handle |

SGLang's [ordinary request schema](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/managers/io_struct.py#L170) carries token IDs, sampling parameters, cache salt and specialized scoring fields, but not general branch positions/self-attention-mask/merge handles. Specialized multi-item scoring fields and speculative tree masks do not establish generic autoregressive fork→merge support.

The favorable internal hook is [ReqToTokenPool](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/mem_cache/memory_pool.py#L274): a row maps physical token order to token KV locations. [FlashInfer packed read streams](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/layers/attention/flashinfer_backend.py#L1727) gather those locations. [ForwardBatch position initialization](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/model_executor/forward_batch_info.py#L1096) normally derives positions from lengths but already separates the position tensor from the KV-location map. [Qwen3 applies RoPE to these supplied positions](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/models/qwen3.py#L176). These are internal integration points, not a supported generic request API.

FlashInfer's [paged prefill path](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/layers/attention/flashinfer_backend.py#L1350) writes KV and attends to the request's mapped prefix with causal new queries. The proved segment decomposition can keep that fast causal kernel: no dense arbitrary mask is required during branch decoding or merged suffix processing. An alternative generic-mask bootstrap is possible through backend metadata, but [fast_prefill_plan explicitly rejects custom_mask](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/layers/attention/flashinfer_backend.py#L2275), so route it to the ordinary planner and validate separately. Do not smuggle ordinary generation through speculative modes; they have different acceptance/counting semantics.

SGLang's [decode graph runner](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/model_executor/runner/decode_cuda_graph_runner.py#L1305) copies incoming explicit positions into captured buffers. This makes graph reuse plausible for fixed batch buckets, but does not certify the new KV ownership/scheduler operations. Perform fork/merge mapping updates outside the graph; only replay already-prepared per-step buffers inside it. Initially use eager bridge/closure prefill and decode-only graphs.

vLLM's [TokensPrompt schema](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/inputs/llm.py#L111) exposes token IDs and common options; it does not carry generic attention masks or semantic position IDs. Its [GPU runner](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/v1/worker/gpu_model_runner.py#L2175) derives positions from computed-token count and immediately passes the same tensor into physical slot mapping. Supporting repeated semantic positions therefore requires separate physical-cache indices, beyond just overriding model RoPE positions. Its [prefix caching](https://docs.vllm.ai/en/latest/design/prefix_caching/) reuses a previously computed prefix; it does not recompute structured hidden states or implement a semantic branch merge. [CUDA graph support](https://docs.vllm.ai/en/latest/design/cuda_graphs/) is independent of mask correctness.

## Minimal SGLang patch architecture

1. Add an internal `StructuredKVHandle(actor_version, layout_digest, canonical_ids, semantic_positions, shared_locations, private_locations, refcount)` and trusted local commands `fork`, `seal`, `merge`, `release`. Use direct model-runner integration first, not public HTTP fields. Each handle pins actual KV tokens even while no ordinary request is running. Preserve allocator ownership/refcounts through abort, cancellation and eviction; ordinary request completion must not free retained branch KV.
2. Start with page size 1 / token-index cache layout if supported by the selected FlashInfer backend/build. Allocate request rows for sibling handles and map each to the same prefix locations plus disjoint private locations. At larger page sizes, partial-page tails need copy-on-write or aligned repacking; aliasing mutable final pages is unsafe. Verify memory cost and allocator behavior before optimizing.
3. Carry explicit positions in `ScheduleBatch` → `ForwardBatch.init_new`; override length-derived positions only for structured handles. Track physical prefix length separately from semantic next position. Path headers, generated canonical path tokens, and forced closures increment branch semantic positions normally. Merge next position is base plus maximum canonical span length, not union token count.
4. Scheduler hooks enqueue a ready path group after width is known, allow independent per-row stop/cap, finalize canonical closure KV, then form the merged request row as shared prefix once plus private tails in order. Only after all sibling handles are sealed does bridge/summary run. Main after native `</think>` retains the existing no-structure guards. Later forks inherit the already-merged exact KV.
5. Initially leave global RadixCache off for structured handles. Explicit handles provide intra-trajectory reuse. If later enabled, cache identity includes actor version, model/tokenizer, semantic position sequence and visibility/layout digest; token IDs alone can collide between causal and structured histories. SGLang [RadixKey cache_salt](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/mem_cache/radix_cache.py#L58) can namespace keys, but does not itself calculate these semantic identities.
6. Return exact raw IDs, temperature, guards and normalized sample logprobs; keep visible assembly separately. Preserve per-call RNG identity across scheduler reordering. Same integer seed does not guarantee same samples between PyTorch multinomial and engine-native sampling kernels; compare teacher-forced distributions first, then use recorded shared uniforms/inverse-CDF selection for a strict sampling identity test.

`adapter_contract_sketch.py` states the minimal trusted internal API and ledger invariants without implementing an engine. The CPU script implements the mathematical cache architecture, not these allocator/scheduler patches. No compiled engine patch is presented as complete.

## Lag-one rollout version contract

Run generation on immutable actor version `v` while the learner updates `v+1`. All four responses in a prompt group and all phases/forks of an episode carry one lease for `v`; release only after its last structured handle and call are released. The learner may consume a complete batch with version gap at most one under the selected off-policy objective; record actor, learner, sampling-policy versions and exact stored actor logprobs.

SGLang [update_weights_from_tensor](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/entrypoints/engine.py#L1592) refreshes engine weights and can flush cache. It does not pin a whole multi-call episode. Its [weight_version logic](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/managers/scheduler.py#L5417) records version changes for live requests, demonstrating that the label is provenance, not an immutable snapshot. [Pause modes](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/managers/io_struct.py#L1824) can retain old KV or retract/recompute requests; neither ensures all phases of a lease stay on one actor. Gate weight refresh on **application leases plus resident structured handles**, not only the engine's instantaneous running-request count. Verify successful cache invalidation before admitting version `v+1`. Separate learner/rollout engines allow overlap without requiring two simultaneous serving actors; an extra actor engine is a later throughput choice, not necessary for correctness.

## Counter/reward boundary under continuous batching

Current `reward.py` charges `min(.4, .02 * (F // 200))` only when correct, and `train.py` verifies each trajectory's F against observed `model.forward` calls. This physical-F reward depends on execution scheduling. Continuous batching across prompts changes which trajectories participate in one invocation; attributing a fractional share or zero cost to cache hits would silently reward scheduler reuse.

Keep three ledgers: **global unique physical engine invocations**, **episode/call-group participation invocations** (one full charge per participating episode per invocation, every sibling group charged once; never fractionally divide a shared cross-prompt invocation), and **frozen isolated HF reference F** derived from the same logical trace. The first is a system metric; the second can support new engine reward billing without dividing by cross-prompt batch size; the third is a fixed-control reward metric and must never be called actual physical F. Bill canonical closure/bridge forwards and cache misses/recompute. Record generated action tokens, injected tokens, prefill tokens, physical cached KV tokens, semantic depth, and cohort membership separately.

For initial speed-only comparison, use the identical frozen reward computation from reference F and label it explicitly. If training adopts trajectory-participation F, that is a reward/protocol change requiring a separate paired control, even if output distributions match. Existing `F <= sampled_tokens` assertions may fail if closure-only forwards are added: either fuse/cache-finalization into existing forwards where valid or revise the schema explicitly; do not hide these calls.
