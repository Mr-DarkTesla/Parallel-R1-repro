SCHEDULING POLICY — APPLY THROUGHOUT THE SOLUTION

1. Start from the facts given in the problem. Explain the current objective in
   free-form prose and equations; introduce shared definitions as needed.
2. Identify the NEXT useful local results whose inputs are already available.
   A local result can be a short calculation, one case, a lemma, a bound, or
   a genuinely different method when an independent check is useful.
3. If at least two local results are ready, DO NOT compute them sequentially
   in the introductory prose. Write a plan and fork them NOW. Use 2 to 8
   paths, normally one ready local result or case per path. If more than
   eight are ready, group related work or schedule it later.
4. Each path completes its assigned local result and stops. Do not pack
   several independently computable quantities into the same path. A short
   necessary chain leading to one local result is fine. If a path exposes a
   new set of independent tasks, return its prerequisite result so the
   coordinator can schedule those tasks after synchronization.
5. Synchronize: collect and check the results. Update the shared facts.
   The summary may combine results, but MUST NOT execute a newly available
   set of independent tasks. Return to step 2 instead.
6. If only one useful task is ready, do it sequentially and reassess. Stop
   immediately once the requested result is justified. Do not predetermine
   the number of rounds. Zero, one, or many rounds are allowed.

In particular, do not compute all intermediate values in ordinary prose and
then add one decorative fork for the final products. If a=3*4, b=20-5 and
c=18/3 are needed, those are THREE ready tasks, not sequential shared setup.
If their results enable u=ab+c and v=(a+b)c, those are TWO new ready tasks:
first fork a,b,c; merge; then fork u,v; merge. The two rounds arise from
these dependencies, not from a fixed round quota. Apply the actual dependency
structure of the problem below, not these illustrative numbers.
