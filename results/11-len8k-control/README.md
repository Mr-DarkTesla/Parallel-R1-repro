# 11: лимиты длины 8192 на старых данных (контроль к 12)

Отличие от 02: длина примера в SFT 8192 вместо 4096 (`scripts/sft_qwen3_0.6b.sh`), длина ответа в eval 8192 вместо 3000
(`scripts/eval_qwen3_0.6b.sh`), `max_tokens` в проверке тегов 8192 вместо 3000 (`scripts/check_tags.py`). Данные те же.
Запуск: `bash scripts/run_experiment.sh 11-len8k-control`.

Мотивация: эксперимент 12 добавляет в SFT длинные примеры ParaThinker, для них нужны лимиты 8192. SFT-данные GSM8K короче 4096,
поэтому SFT здесь совпадает с 02r; разница с 02r показывает только влияние лимита eval (обрезка длинных ответов на 3000).

Результат (2026-10-06, SFT 230 шагов, 16:42–18:07; eval и проверка тегов до 18:37): лимит 8192 вместо 3000 точность не изменил.
Парное сравнение с 02r по 1233 задачам (`paired_compare.py`, 11 − 02r, пункты, bootstrap 95% CI): **−0.04 [−0.59, 0.50]**;
AIME24 +0.21 [−0.42, 0.83], AIME25 −0.21 [−0.83, 0.42], AMC23 −0.31 [−3.12, 2.50], MATH300 (x1 и x8 вместе) −0.28 [−2.00, 1.44],
LIMO +0.06 [−0.40, 0.52] (`paired_02r_vs_11.json`). Средние: AIME24 0.8, AIME25 0.2, AMC23 10.6, MATH300 27.2 (x8: 26.9),
LIMO 1.2 (`compare.md`). Ответов без `Final Answer` стало меньше (LIMO 3.7% → 1.9%, MATH300×8 1.1% → 0.8%), но на точность это
не повлияло. Структура тегов на уровне 02r: правильных тегов 88.3% на AIME/AMC/MATH300 (`eval_apo.txt`), полностью корректных
ответов 78.4%; в свободной генерации финального чекпоинта MATH300 T=0 — 72% корректных ответов / 78% правильных тегов
(у 02r 67% / 79%, но это шаг 184: проверка тегов 02r для шага 230 не делалась).

Вывод: 11 — рабочий контроль для 12 с теми же лимитами. Разница 11 и 02r в пределах шума eval (02 против 02r: AIME24 pass@16 10.0
против 3.3); один сид, SFT 11 и 02r отличаются только `max_length` в SFT, которого данные GSM8K не достигают.
