# Чекпоинты авторов на наборе слайда «Точность против болтовни»

Задачи те же, что у точек SFT + RL и RL без SFT: MATH500 (500 задач) и AIME 2024, 2025, 2026 (по 30). Каждый набор весит четверть, как в `plot.py` RL-веток.
Других весов, кроме этих двух, авторы не публиковали: на Hugging Face есть только `Parallel-SFT-Unseen` и `Parallel-R1-Unseen_Step_200` (S2, шаг 200).

| Модель | Точность, % | Форварды на ответ | Форков на ответ |
|---|---|---|---|
| RL авторов, S2 шаг 200 | 26.8 | 1663 | 0.69 |
| SFT авторов | 20.0 | 1189 | 1.71 |

Старая точка на слайде (38.8 %, 1539) посчитана на MATH300 авторов без AIME 2026. Новая ниже из-за MATH500. В MATH300 авторов все 316 ответов целые, а RL-чекпоинт, обученный на DAPO с целыми ответами, почти всегда пишет в `Final Answer` целое число, даже если сам выше вывел дробь: «the value is 14/3», а затем «Final Answer: 14». На задачах MATH500 с целым ответом (62 % набора) он решает 87.2 %, на остальных около 15 %. SFT ещё пишет нецелые ответы, поэтому на MATH500 обходит RL (63.4 против 59.8).

Если вместо MATH500 взять MATH300 авторов (их исходная метрика, прошлый прогон с бюджетом 16k: RL 82.3 % при 976 форвардах, SFT 74.4 % при 633), а AIME 2024–2026 оставить из этого прогона, точка RL будет 32.4 % при 1652 форвардах, SFT — 22.7 % при 1165. Такая точка выше, но её MATH-часть посчитана на других задачах, чем у остальных точек слайда.

| Набор | RL: точность / форварды | SFT: точность / форварды |
|---|---|---|
| AIME 2024 | 17.5 / 1966 | 6.9 / 1468 |
| AIME 2025 | 16.5 / 1717 | 5.8 / 1195 |
| AIME 2026 | 13.5 / 1948 | 3.8 / 1362 |
| MATH500 | 59.8 / 1020 | 63.4 / 729 |

Как получено. Промпт и параллельный роллаут авторов (два пути на блок, `scripts/bench/eval_rollout.sh`), temperature 1, top_p 1, бюджет ответа 30720 токенов: модель вмещает 32768 позиций, а 95 % ответов короче 4.4 тыс. токенов. Чтобы снизить шум среднего, каждая задача AIME решалась 16 раз, MATH500 — 4 раза; на слайде у наших точек по одному ответу на задачу, ожидаемое значение то же. Точность — `accuracy_robust` из `scripts/bench/score.py` (ответ из `\boxed{}` или строки `Final Answer:`, сравнение через math_verify). Строгая проверка авторов даёт 14.2 % у RL и 17.0 % у SFT.

Форварды — шаги декодирования на критическом пути (`scripts/bench/lengths.py`): токены основной цепочки, в каждом блоке самый длинный путь и summary. Prefill выдаёт следующий токен, поэтому это то же F, что у наших точек. Отличие: наши точки считали вызовы `model.forward` прямо в рантайме, а здесь шаги восстановлены по тексту ответа. Наш рантайм формат авторов не исполняет: ему нужна ширина в заголовке `<Parallel>`.

Файлы: `points.csv` — точки для графика; `authors-rl200.json`, `authors-sft.json` — сводки по наборам; `slide-*/results`, `slide-*/lengths` — метрики прогонов; `*.generations.jsonl.gz` — ответы без промпта. Данные строит `scripts/bench/make_slide_data.py`, сводку — `scripts/bench/slide_summary.py`.
