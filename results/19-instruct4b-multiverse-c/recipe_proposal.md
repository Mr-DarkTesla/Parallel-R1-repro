# Вариант C: предлагаемый SFT-рецепт (не запускать без одобрения Виктора)

## Модель и токены
- Старт: P (Qwen3-4B + 6 тегов Parallel-R1, ID 151669-151674) + 6 новых тегов `<Goal> </Goal> <Outline> </Outline> <Conclusion> </Conclusion>`,
  ID 151675-151680 (свободные строки, vocab весов 151936 не меняется, resize не нужен). `<Summary>` в формате C не используется.
- Tied embeddings: строка тега одновременно вход и выход (логит). Поэтому инициализация и обучение строк критичны (FINDING-root-tag-embeddings).

## Инициализация строк тегов (новых и, по решению, старых шести)
- Сейчас у P строки = среднее подтокенов, норма 0.61-0.71 при норме обычных токенов 0.78-1.1, попарный cos 0.40-0.74, после SFT 13/14/15 сдвиг ~2%.
- Предложение: e(tag) = mean(подтокены слова, напр. "goal") + d_open/close + r_tag, где d_open/close — общий для открывающих/закрывающих
  вектор, r_tag — случайный ортогональный остальным тегам; масштаб до средней нормы обычных токенов (~0.9). Цель: попарный cos тегов <= 0.3,
  открывающий и закрывающий тег различимы. Проверка до обучения: cos-матрица 12x12 и норма.

## Обучение строк тегов
- Adam нечувствителен к масштабу градиента, поэтому множитель градиента строк не работает; отдельный lr для строк одного параметра в FSDP неудобен.
- Предложение: этап 0 «прогрев эмбеддингов»: заморожено всё, кроме embed_tokens; градиент всех не-теговых строк обнуляется хуком
  (при weight_decay=0 у таких строк Adam-шаг ровно 0); lr 1e-3, ~50-100 шагов на тех же SFT-данных, loss по ответу.
  Затем обычный SFT всех весов (lr 1e-5, cosine, warmup). Альтернатива: отдельный параметр-дельта 12 x d для строк тегов со своим lr.
- Метрика до/после: teacher-forced точность и вероятность правильного тега на позициях тегов в dev-части SFT-данных (минуты GPU).

## Данные и шаблон
- Только thinking-режим: шаблон Qwen3 enable_thinking=True, ответ = `<think>\n...блоки...\n</think>\n\n` + неизменённый финальный ответ Qwen.
- Пул: 460 задач Multiverse-1K/s1K без пересечений с eval; правильные (math_verify), не обрезанные трассы C0 с T 0.6/top_p 0.95/top_k 20.
- 1-2 трассы на задачу (разные по структуре), плюс ~20% правильных трасс без блоков (учит не ветвиться без нужды). Строгий фильтр
  автоматическими проверками (checks.py, check_mask.py) и выборочное независимое ревью.
- Открытый вопрос: только thinking или смесь с no-thinking. Предложение: не смешивать с GSM8K Parallel-R1 no-thinking (14f ломает thinking:
  MATH dev 75.6 против 93.1 у C0, ~27% зацикливаются до 16k); если нужен no-thinking — self-distill обычных no-thinking ответов C0 (как E4).

## Маска, позиции, длина
- data.structure=multiverse (multiverse_structure.py): вложенные блоки, пути-соседи взаимно невидимы, позиции каждого пути от общей базы,
  после блока продолжение от самого длинного пути; промежуток "\n" между </Path> и <Path> относится к следующему пути.
- max_length 16384 (p50 Multiverse-1K ~11k, 84% <= 16k). Плотная маска 16k x 16k: float32 1 GiB на образец в даталоадере
  (+bool 256 MiB), внимание без flash-attn (SDPA с произвольной маской). Нужен тест памяти/скорости на 1 шаге с микробатчем 1 и 2
  до запуска; при нехватке — маска как bool с обрезкой до длины батча до перевода во float, либо flex_attention (torch 2.6) с блочной маской.
- Объём по пилоту: ~320 пригодных трасс (~10k токенов) + ~20% без блоков, ~3-4M целевых токенов (цикл 1: 1.7M). Трассы > ~15.5k токенов
  до конвертации не брать (в пилоте 2/16 вышли за 16k после тегов).
- Обучение: global batch 32, lr 1e-5, cosine, warmup 5%, 2-3 эпохи; шаги фиксировать заранее.

## Оценка (нужна доработка кода оценки)
- Genuine parallel rollout сейчас под формат Parallel-R1. Для C нужен rollout Multiverse: после `</Goal>` число путей = числу `<Outline>`,
  путь i стартует с префикса `<Path>\ni:`, после закрытия всех путей — склейка и продолжение с `<Conclusion>`, с вложенностью до 2.
- Обязательно: thinking 16k на MATH dev и dev-наборы, токены суммарно и по шагам декодирования, обрывы, доля валидной структуры.
