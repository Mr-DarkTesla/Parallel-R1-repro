```python
import json, sys
from collections import Counter, defaultdict
from pathlib import Path

base = Path('outputs/instruct4b-2026-10-06')
sys.path.insert(0, str(base / 'dataset_survey/scripts'))
import leakcheck as L

corpus = L.Corpus(str(base / 'dataset_survey/eval_corpus'))
rows = [json.loads(x) for x in open(base / 'exp21_06b/data/pool.jsonl')]
pairs = Counter()
flagged_rows = set()
math_test = set()
for row in rows:
    for hit in corpus.check(row['question'], row['answer']):
        name = hit['eval_set']
        if '(info)' not in name and hit['leak']:
            pairs[(row['source'], name, hit['tier'])] += 1
            flagged_rows.add(row['id'])
        if name == 'math_test_full(info)' and hit['tier'] in ('dup', 'variant'):
            math_test.add(row['id'])
print(len(flagged_rows), len(math_test), pairs)
```

Сверка `build_pool.py` с результатом: для каждого исходного нормализованного ряда восстановлен список удаляемых ID из `leak/*.hits.jsonl` по условию кода: любой `leak`/`tier` против неинформационных eval; `dup`/`variant` против `math_test_full(info)`; `remove` и `review` из `*.residual_pairs.md`. Затем в исходном порядке применены `ORIGIN`, пустой ответ, повтор вопроса и ограничение формата ответа. Для ARC дополнительно проверены `answerKey` и наличие его в `choices.label`. Полученные списки ID **полностью совпали по порядку** с пулом для MATH, GSM8K и ARC. Сам `build_pool.py` повторно не запускался, так как он перезаписывает текущий пул.

Это 7,2% ARC-части и 1,4% всего пула. Если решено оставлять слабые совпадения, восьмёрку `dup/variant` как минимум надо убрать; особенно пару про единицы расстояния и пару про почву.

## Пределы проверки

- Проверены локальные `pool.jsonl`, исходники и eval-корпус. Копия пула на поде и фактически выбранные для SFT строки не проверялись.
- v2 выявляет текстовые совпадения и близкие формулировки, но не гарантирует отсутствие сильных перефразов и переводов. В документации survey на ручных контрольных примерах указана полнота 16/33 для перефразов и 4/8 для переводов.
- `weak` на преобразованных ARC-вопросах часто вызван общими вариантами и фразой о формате ответа. Все 305 пар вручную не прочитаны; вывод «удалить 243» нужен для буквального соблюдения текущего автоматического правила, а не доказательство, что каждая пара содержательная утечка.
