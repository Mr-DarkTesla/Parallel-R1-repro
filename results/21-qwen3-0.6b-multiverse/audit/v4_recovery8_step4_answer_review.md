# Ручная проверка v4 recovery8, шаг 4

11 октября 2026. Независимо прочитаны все 40 masked greedy-ответов из
[`v4_recovery8_step4_masked_pilot.tgz`](../eval_archives/v4_recovery8_step4_masked_pilot.tgz): условие, gold, рассуждение, внешний ответ и каждая попытка `<Parallel>`.

Внешний ответ засчитывается после закрытого `</think>` независимо от
качества разметки рассуждения. «Верное значение где-либо» допускает
явно полученный корректный промежуточный итог. Полный нумерованный
блок требует валидной грамматики всего ответа. Строго полезный блок
дополнительно требует двух содержательных, верных и независимых
путей, корректного объединения и отсутствия готового ответа до блока.

| Показатель | Число |
| --- | ---: |
| Буквенный автоматический `acc` | 23/40 |
| Строгий автоматический `acc_robust` | 27/40 |
| Верный внешний ответ после `</think>` | 27/40 |
| Верное значение где-либо в выводе | 27/40 |
| Попытка блока | 16/40 |
| Полный нумерованный блок в целом ответе | 14/40 |
| Строго полезный независимый блок | 1/40 |
| Обрезано без завершения | 4/40 |
| Теги вне `<think>` | 0/40 |

`acc_robust` совпадает с ручной проверкой всех 40 внешних ответов:
ложных плюсов и минусов нет. Буквенный `acc` пропускает четыре
правильных ответа из-за формы внешней строки:
`gsm8k-train/43,279,374,379`.

Полные нумерованные блоки: `gsm8k-train/653`,
`math-test/9,38,51,53,65,71,87,88,98,108,117,130,137`.
Невалидны из-за незакрытых или вложенных структур `math-test/29,93`.

Единственный строго полезный блок, `math-test/9`, разбирает два
независимых знаковых случая уравнения с модулем: Path 1 получает
`3/2`, Path 2 получает `-1/8`, а Conclusion выбирает меньший корень.

Остальные полные блоки не проходят смысловой порог. У
`gsm8k-train/653`, `math-test/51,53` решение уже готово до блока;
`/65,87,88` оставляют один Path почти пустым, причём `/88` ещё и
ошибочно утверждает `d=5`; `/71,98,117,130,137` имеют неверные пути
или выводы; `/108` дублирует один и тот же вывод `y=36` в обоих
путях. У `/38` внешний ответ `49` верен, но второй Path получает
неверный центр круга и максимум `1`, поэтому семантически блок
непригоден.

Обрезаны `gsm8k-train/82,232,580` и `math-test/129`; ни один не
содержит корректного результата. Теги всех 16 попыток остаются
внутри `<think>`.

## Сопоставление с исходным v4 step56

По верным внешним ответам step4 сохраняет **27/40**, как v4 step56.
`acc_robust` вырос с 26/40 до 27/40, поскольку recovery-ответ
`gsm8k-train/279` теперь принимается парсером. Структура хуже: вместо
19 полных блоков и двух строго полезных (`math-test/9,36`) у step56
получено 14 и один. Существенный регресс `math-test/36`: в step56
были верные независимые проверки границ и интервал `(-√3,√3)`, а
step4 выдаёт неверное множество всех чисел, кроме `±√3`.
