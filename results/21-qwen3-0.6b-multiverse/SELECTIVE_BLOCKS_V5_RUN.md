# Выборочные блоки v5: больше разных задач

11 октября 2026. [Карточка данных](DATASET_SELECTIVE_BLOCKS_V5.md),
[хранение чекпоинтов](CHECKPOINT_RETENTION.md).

Смесь v2: 2748 train и 63 validation. Доля положительных ответов
не менялась: 555 train и 24 validation. Вместо 185 уникальных
положительных train-ID использованы все 305 ID из v1; объединение
результатов снова находится после `</Parallel>` внутри `<think>`.
Автоматический аудит 579 положительных строк прошёл, независимая
проверка 30 примеров: 30/30 полезных блоков, 0 неверных ответов.

Обучение на одном нашем H100: 64 шага, batch 32, microbatch 4,
lr `1e-5`, `tag_lr_mult=100`, `parallel_text_loss_weight=1.0`,
максимум 4096 токенов. Validation loss после шага 64: **0,292481**.
Восемь BF16 экспортов шагов 8–64 проверены и перенесены на
собственный PVC `/checkpoints/exp21-m1-selective-v5`. До отбора
пяти лучших они занимают около 9,1 GiB; на томе с уже выбранными
пятью моделями v4 осталось 3,9 GiB.
[Архив рецепта и обучения](eval_archives/selective_v5_train_meta.tgz).
Порядок `DistributedSampler` показывает, что за 64 шага модель реально
увидела 415 из 555 положительных строк и 280 из 305 уникальных
положительных задач. [Точный подсчёт](audit/selective_v5_train_exposure.md).
Это ограничивает вывод об эффекте разнообразия данных: 25 задач с
блоками в обучение вообще не попали.

## Ранний шаг 8

На том же пилоте шаг 8 дал 6/40 по строгому `acc_robust`, но ручное
чтение нашло 33/40 верных самостоятельных ответов после закрытого
`</think>`. Ещё один верный ответ остался внутри обрезанного
рассуждения; в основной счёт он не входит. Модель не поставила ни
одного тега Multiverse, обрезаний было 6/40. Это показывает, что
буквальный разбор `Final Answer:` сильно занижает точность раннего
шага, а высокая точность сама по себе не означает освоения блоков.
[Проверка с ID ответов](audit/selective_v5_step8_answer_review.md).

## Состояние полного прохода по чекпоинтам

Одинаковый пилот завершён для всех восьми шагов. Внешний ответ
засчитывается только после закрытого `</think>`; строка `Final Answer:`
для этой ручной колонки не обязательна. «Полный блок» здесь требует
корректной разметки всего вывода, поэтому локально закрытый блок в
позднее повреждённом выводе не засчитывается.
