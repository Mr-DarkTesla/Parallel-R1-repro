# Выборочные блоки v4: итог внутри Conclusion

11 октября 2026. [Карточка данных](DATASET_SELECTIVE_BLOCKS_V4.md),
[хранение чекпоинтов](CHECKPOINT_RETENTION.md).

## Обучение

Та же смесь v2: 2 748 train и 63 validation, в том числе 555 train
и 24 validation с параллельным блоком. Во всех положительных ответах
исходный текст двух Path оставлен, итоговая арифметика перенесена
в `<Conclusion>`. Проверка датасета и независимое чтение 30 задач:
29/30 строго полезных блоков, 0/30 неверных ответов.

Один наш H100, post-trained Qwen3-0.6B, 64 шага, batch 32,
microbatch 4, базовый lr `1e-5`, `tag_lr_mult=100`,
`parallel_text_loss_weight=1.0`, максимум 4 096 токенов.
Восемь экспортов BF16 сохранены после шагов 8, 16, 24, 32,
40, 48, 56 и 64 на собственном PVC `/checkpoints`.
Обучение завершено, validation loss на шаге 64 равен 0,304656.
[Архив обучения](eval_archives/selective_v4_train_meta.tgz) содержит
точный рецепт, использованные строки, loss и журнал.

## Пилот шага 64

Те же 20 GSM8K и 20 MATH dev-задач, что для C0, v1, v2 и v3;
masked greedy-декодер не вставляет теги. Четыре поднабора и полные
ответы сохранены в [архиве](eval_archives/selective_v4_step64_masked_pilot.tgz).

| Метрика | Шаг 64 |
| --- | ---: |
| Верный ответ, ручная проверка и `acc_robust` | 26/40 |
| Полный блок внутри `<think>` | 19/40 |
| Верный ответ и синтаксический блок | 10/40 |
| Строго полезный блок после повторной проверки всех 19 блоков | 2/40 |
| Теги вне `<think>` | 1/40 |
| Обрезанные ответы | 2/40 |
| Средняя длина ответа | 608,4 токена |
| Средняя расчётная глубина форвардов | 582,8 |

По источникам верны 16/20 GSM8K и 10/20 MATH. Независимый
Первый рецензент нашёл три полезных блока. Повторная проверка исключила
`gsm8k-train/653`: все вычисления уже сделаны до блока, он их
повторяет. Строго полезны только `math-test/9` и `math-test/36`.
Остальные 17 синтаксических
блоков содержат повторяющиеся или зависимые пути, ошибочную
арифметику либо всю работу в Conclusion. Четыре верных GSM8K
ответа (`43`, `279`, `379`, `462`) строгий `acc` ошибочно отверг;
`acc_robust` и ручная проверка дают 26/40. Ложных плюсов у
`acc_robust` рецензент не нашёл.
[Постатейный разбор всех 19 блоков](audit/selective_v4_step64_semantic_review.md).
Одна строка сырого `gsm8k_dev10.jsonl` содержит U+2028 внутри
текста ответа: читать архив через разделитель `\n`, не через
`str.splitlines()`, который считает U+2028 новой строкой.

Для сравнения, v2 дал 30/40 верных и 0/40 полезных блоков,
исходная C0 дала 34/40 верных без блоков. Это пока пилот
одного шага; остальные семь чекпоинтов затем прошли те же
40 задач. Полный dev и frozen для v4 не запускались.

Парная разница точности шага 64: против исправленной C0
**−20,0 [−35,0; −7,5] п.п.**, против v2
**−10,0 [−25,0; +5,0] п.п.** (95% bootstrap-ДИ, одинаковые вопросы).
Доля синтаксических блоков против v2: +5,0 [−7,5; +20,0] п.п.
Сводка и остальные интервалы сохранены в
`audit/selective_v4_step64_pilot40_summary.json` и
`audit/selective_v4_step64_vs_{c0_corrected,selective_v2}_pilot40.json`.

завершёнными финальными ответами: девять следуют без нужного оформления

сравнение 33/40 с C0 завышало качество по целевому протоколу.

Шаги 24, 40, 48, 56 и 64 сохранены на отдельном PVC.
Шаг 48 восстановлен из временного экспорта и проверен перед заменой
шага 8; сырые ответы всех восьми шагов сохранены.

Строго полезных блоков у v4 мало даже на лучшем шаге;
следующий кандидат v5 обучается с исходным расположением
объединения после `</Parallel>` и большим разнообразием задач.
