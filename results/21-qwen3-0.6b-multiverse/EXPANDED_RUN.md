## Данные и проверка

Для каждого метода объединены прежние 187 и дополнительные 180 задачи, всего 367 разных структурированных решений. У M1 и M2 одинаковое распределение: 140 GSM8K с целым ответом, 93 MATH с целым, 71 MATH с дробью, 63 MATH с выражением. Новые ID методов не совпадают; всего методы разделяют 147 старых задач. Это ограничивает причинное сравнение методов, хотя объём и состав равны.

В каждом варианте структурированный ответ повторяется трижды. Те же 300 правильных ответов Qwen no-thinking и 300 thinking повторяются дважды в каждом варианте, чтобы доля собственных ответов Qwen осталась близкой к прежней: 1200/2301 = 52,15% против 600/1161 = 51,68% в первой SFT. Генерации Qwen не изменены; повторение не добавляет разных задач. Для контроля удалены только структурные теги из ответов того метода, который будет выбран по dev.

Общие validation ID дают по 50 строк на вариант: 24 структурированные копии, 14 no-thinking и 12 thinking ответов Qwen. Новые 180 задач каждого метода находятся только в train. Train каждого варианта содержит 2251 строк: 1077 структурированных, 586 no-thinking и 588 thinking. 64 шага с глобальным пакетом32 обработают 2048 строк за один проход с перемешиванием; часть строк при таком бюджете шагов не будет увидена. Это одинаково для M1, M2 и выбранного контроля.

[Машинный аудит четырёх подготовленных вариантов](audit/expanded_sft_parity.json) подтвердил числа строк, общие validation ID, сверку текстов всех 9204 строк parquet с исходными pair/replay JSONL, отсутствие точных нормализованных совпадений вопросов между train и val, одинаковые replay во всех вариантах, дословное удаление тегов в обоих возможных контролях, одинаковое распределение M1/M2 и ограничение 4096 токенов (максимум 3838). Независимое ревью также проверило реальные 9204 строки и не нашло блокирующей ошибки. [Фиксированные ID и рецепт разбиения](audit/expanded_sft_split.json), [код подготовки](../../scripts/exp21/prepare_expanded_sft.py), [код проверки](../../scripts/exp21/audit_expanded_sft.py). Файлы train/val: `data/sft_{m1,m2,control_m1,control_m2}_expanded_{train,val}.parquet`.

## Запуск после восстановления PVC

Сначала проверить собственные StatefulSet/PVC, штатное размещение, готовность B, одну видимую GPU, локальные `/work/assets/models/Qwen3-0.6B-mv` и `/work/venv`, свободное место и отсутствие запущенной старой очереди. Затем скопировать восемь parquet-файлов на B в `/work/exp21/data/` и проверить число строк на pod. Не монтировать чужие профили и не задавать nodeSelector вручную.

На B использовать существующую очередь GPU0. Для первых двух вариантов одинаковый вызов тренера:

```bash
STEPS=64 LR=1e-5 BATCH=32 MICRO_BATCH=4 MAX_LENGTH=4096 TAG_LR_MULT=100 \
  bash /work/exps/21-qwen3-0.6b-multiverse/scripts/exp21/pod_jobs.sh sft exp21-m1-expanded \
  /work/exp21/data/sft_m1_expanded_train.parquet /work/exp21/data/sft_m1_expanded_val.parquet
```

Для M2 заменить `m1` на `m2` во всех трёх именах. `CUDA_VISIBLE_DEVICES=0` выставляет `queue_runner.sh`. `pod_jobs.sh` использует начальный post-trained Qwen3-0.6B с десятью подготовленными спецтокенами, маску Multiverse и `optim.tag_lr_mult=100`. После каждого запуска проверить `DONE`, bf16 экспорт, `step:64`, журнал рецепта и долю увиденных строк; не считать успешную постановку в очередь завершённым обучением.

Затем оценить M1/M2 на dev GSM8K, MATH, ARC, MMLU-Pro в двух режимах, IFEval, грамматику блока в последовательном и масочном/ветвящемся протоколе, длину, расчётные форварды, реальные вызовы декодера и обрезания. Выбрать метод по dev до frozen. Только после выбора обучить соответствующий `control_m1` или `control_m2` на тех же текстах без тегов и с теми же 64 шагами, затем посчитать парные интервалы против исходной модели и этого контроля. Frozen-наборы открыть только для выбранного варианта. Старые таблицы результатов относятся к обучению на 187 задачах, их нельзя подписывать как результат этих новых parquet.
