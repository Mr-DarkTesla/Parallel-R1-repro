# Qwen3-4B: продолжение на собственных проверенных траекториях

11 октября 2026, 13:17 МСК. Данные собраны и проверены; обучение
**ожидает завершения M2** в очереди одной нашей H100. Метрик этого
продолжения ещё нет.

Исходные веса двух плеч: соответствующие tagged/plain модели 4B
mixed401 шага 128. В каждом плече 231 train-строка: 34 дважды
проверенные 4B-траектории с блоками внутри `<think>`, предъявленные
по три раза, и 129 собственных верных 4B ответов без блоков. Два
плеча имеют одинаковые вопросы, слова, числа и порядок; plain
удаляет только десять спецтегов. Validation: прежние одинаковые
50 строк. [Карточка и контроль утечек](DATASET_QWEN4B_FOCUS34.md).

Рецепт: по 32 шага каждому плечу, batch 16, microbatch 1, основной
lr `1e-6`, `optim.tag_lr_mult=100`, `+data.structure=multiverse`,
обычный CE. Сохраняются шаги 8, 16, 32; сначала на том же fixed40
оценивается финальный шаг 32 обоих плеч. Это отдельное продолжение:
его нельзя трактовать как чистый эффект числа шагов mixed401, потому
что одновременно изменены состав данных и основной lr. Между
tagged и plain нового продолжения эти параметры одинаковы.

Скрипт: `scripts/exp21/run_qwen4b_focus34_after_queue_pod.sh`.
Он ждёт `M2_SPANFOCUS_EVAL_DONE`, затем проверяет отсутствие GPU
процесса, исходные веса и отчёт CPU-проверок. На нашем pod
`vcharkin-exp-vm-0` загружены четыре parquet, отчёт и скрипт;
проверены размер, схема 231/50 строк и `bash -n`. Ожидающий
процесс PID 87083, журнал `/work/exp21/qwen4b_focus34/runner.log`.
Маркер `ATTEMPT_DONE` пишется и при ошибке, `EVAL_DONE` только после
обоих полных fixed40. Frozen-наборы этим запуском не открываются.
