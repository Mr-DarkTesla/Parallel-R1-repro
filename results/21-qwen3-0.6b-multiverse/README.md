# Qwen3-0.6B: SFT с параллельными блоками Multiverse

Первый набор M2 не прошёл дополнительную независимую проверку рассуждений и исключён из окончательного сравнения. После полного аудита собран новый набор из 187 решений: 147 задач совпадают с M1, 40 заменены. Независимая проверка новых примеров дала 40/40 полезных блоков и верных финальных ответов. История очистки и точный состав находятся в [карточке M2](DATASET_M2.md).

После основного сравнения проверен декодер с той же маской путей и позициями, что при SFT. Он не вставляет теги и дал 16/20 полных нумерованных блоков на малых срезах GSM8K и MATH dev; точность MATH осталась низкой. Это отдельный поисковый пилот, не замена полному dev-сравнению. [Диагностика и ответы](FOLLOWUP_AUTONOMY.md).

Отдельная проба `thinking=True` выявила, что M1 ставит теги преимущественно после `</think>`: на одинаковых 20 GSM8K dev-задачах ни одна из исходных четырёх моделей не завершила блок внутри рассуждения. [M1-thmix](DATASET_M1_THINKING.md) обучен переносить блок внутрь `<think>`; с масочным декодером он завершил 16/20 блоков, но верно ответил только на 6/20 задач. В последовательной генерации верных ответов 8/20 против 17/20 у исходного M1. Это малая диагностическая выборка, вариант не выбран. [Протокол, ответы и интервалы](THINKING_FOLLOWUP.md).

## Протокол

Сравнивается post-trained `Qwen/Qwen3-0.6B`, а не Base. Подготовленная модель P06 добавляет десять специальных токенов `<Parallel>`, `<Goal>`, `<Outline>`, `<Path>`, `<Conclusion>` и их закрывающие варианты (ID 151669–151678). Инициализации строк различимы: наибольший попарный косинус 0,482. В SFT используется `multiverse_structure.py` из exp/19: пути одного блока не видят друг друга и получают позиции независимо. Новые строки обучаются с `optim.tag_lr_mult=100` из exp/20. В обычных ответах без блока сохраняется стандартная причинная маска.

M1: Claude через VK AI Proxy пишет решение сразу с блоками. M2: Qwen пишет верный ответ сама; Claude задаёт только границы блоков и план, исходный текст и числа сохраняются. У окончательных наборов по 187 задач с одинаковым распределением источников и типов ответов; 147 ID совпадают, 40 M2 заменены после дополнительной проверки. Каждая строка повторяется трижды, добавляются те же 300 верных собственных ответов Qwen no-thinking и 300 thinking. Train/val содержат 1111/50 строк с разбиением по задачам и одинаковыми числами строк каждого вида; проверка в `data/sft_parity_audited_m2.json`. Источники, отсев, утечки и примеры: [пул](DATASET_POOL.md), [M1](DATASET_M1.md), [M2](DATASET_M2.md), [контроль M1](DATASET_CONTROL_M1.md).

M1, очищенный M2 и контроль M1: один H100, 64 шага оптимизатора, глобальный пакет 32, микро-пакет 4, максимум 4096 токенов, cosine schedule, lr `1e-5`, множитель lr тегов 100. Все три завершили 64 шага и bf16 экспорт. Контроль обучен тем же рецептом и с тем же обучающим запросом на текстах M1 после удаления только структурных тегов. Окончательный выбор делается по dev и IFEval до frozen-наборов. [Рецепты и журналы обучения](TRAINING.md).

Оценка на dev GSM8K, MATH, ARC и MMLU-Pro в обычном no-thinking и thinking, а также IFEval в обоих режимах. Число задач и ответов на задачу: GSM8K 296×4, MATH 482×2, ARC 299×4, MMLU-Pro 999×1, IFEval 541×1. Для грамматики дан отдельный запрос Multiverse в no-thinking. `accuracy_robust` проверяет математический ответ, для IFEval приводится доля строгого выполнения запросов. Все парные 95% интервалы получены из 10 000 бутстрэп-выборок задач каждого набора: повторные сэмплы одной задачи остаются вместе; поправка на множественные сравнения не применялась. Длина считается токенизатором проверяемой модели, число последовательных форвардов считает каждый корректный блок по самому длинному Path; невалидный ответ не получает экономии. Доля обрезаний учитывается отдельно.

IFEval технически лежит в каталоге `frozen` оценочного конвейера, но по заданному протоколу проверялся у всех вариантов и участвовал в выборе метода. В качестве неоткрытых при выборе frozen-наборов оставлены APO, ARC, MMLU-Pro и LIMO; их оцениваем только у выбранного M1.

Проверка Multiverse проводится двумя способами. Обычный последовательный декодер показывает поведение модели без управления ветвями. Для измерения независимых путей `multiverse-branch` каждый Path генерируется из одного Goal с принудительно заданным номером; декодер добавляет открывающий Path и закрывающий тег после того, как модель остановилась на нём. Затем пути объединяются и модель сама пишет заключение. На этапе путей выполняется требуемая независимость. После объединения vLLM использует обычные позиции, поэтому это приближение к полному декодеру с позициями `multiverse_structure.py`. Грамматическая доля этого протокола не доказывает, что модель сама расставляет все теги; последовательная генерация и действия декодера приведены отдельно.

## Качество обучающих данных

Исходный пул содержит 16 547 задач из MATH train, GSM8K train и ARC train. Все 296 GSM8K dev удалены из GSM8K train, как и два близких варианта. `leakcheck.py` v2 против всех наших eval-наборов и полного MATH test дал 0 сигналов, 0 точных дублей и 0 вариантов MATH test; ограничения проверки записаны в [карточке пула](DATASET_POOL.md). M1 и очищенный M2 используют по 187 задач: 86 с целым ответом, 63 с дробью и 38 с выражением; совпадают 147 ID.

Сбор M1: Claude написала 1288 прошедших проверку решений из 3400 задач, стоимость $33,76. Сбор M2: 241 прошедший план из 1716 первых ответов Qwen и 61 из 326 альтернативных верных ответов, стоимость $15,55. Полный аудит рассуждений M2 добавил учтённые $3,66; ещё $0,42 стоил малый пилот, который не вошёл в обучающие данные. Учтённая сумма через прокси не менее $53,39 при лимите $200: у девяти неуспешных аудиторских запросов отсутствует цена, поэтому точный итог по локальному журналу не установлен. В M2 после удаления тегов и добавленного плана исходные слова и числа Qwen восстановимы; контроль без тегов сохраняет те же слова, Outline и Conclusion.

Я прочитал по 20 примеров каждого метода. Дополнительная независимая проверка первоначального M2 обнаружила 7 содержательных ошибок среди 30 примеров при верных финальных ответах. После полного аудита 277 кандидатов оставлены 187 M2; новая моя выборка дала 20/20 полезных блоков и верных итогов, независимое ревью другой выборки 40/40. Ещё 30 M1 прошли независимый разбор без ошибки. Причины исключений и сами тексты указаны в [карточке M1](DATASET_M1.md), [карточке M2](DATASET_M2.md) и папке `audit/`.

Два проверяемых примера: в `math-train/2059` M1 разделяет подсчёт случаев с двумя чёрными и двумя белыми шарами на независимые Path с результатами 196 и 168; Conclusion складывает их и даёт вероятность `4/5`. В `gsm8k-train/1865` M2 сохраняет вычисления Qwen `2 + 6 + 5 = 13` и `2 + 10 + 10 = 22` в двух Path, а за блоком оставляет исходное `13 + 22 = 35`. Точные фрагменты с тегами приведены в карточках; полные строки в `data/pair_final_m1.jsonl` и `data/pair_audited_m2.jsonl`.

Успешная разметка блока сама по себе не доказывает улучшения математического рассуждения.

Цена формата существенна: M1 на специальном запросе даёт 17,74% MATH против 40,87% в обычном no-thinking. Проверка `math-test/9` показала реальную ошибку знака в решении задачи с модулями, а не только ошибку извлечения ответа. За счёт параллельных путей число форвардов меньше длины самого структурного ответа, но по сравнению с коротким обычным ответом экономия не гарантируется.

При обычной последовательной генерации на исходном специальном запросе доля ответов с грамматически верным блоком равна нулю и у M1, и у M2: модель после первого Path часто переходит к Conclusion. В ветвящемся протоколе декодер сам подставляет открывающий `<Path>`, номер и закрывающий `</Path>` после остановки модели; начало блока, Goal, Outline, содержание путей и Conclusion пишет модель. Для M1 закрытие путей моделью наблюдалось в 97,8–99,7% начатых путей; детали по наборам в `audit/m1-dev-mvb.json`. Этот результат не означает самостоятельной расстановки всех тегов при обычном декодировании.

## Вывод по сравнению методов

На обычном запросе M1 улучшил no-thinking точность относительно исходной модели на всех четырёх dev-наборах: парные интервалы прироста не включают ноль. В thinking интервал прироста не включает ноль только на MMLU-Pro; для GSM8K, MATH и ARC он включает. Разница IFEval с исходной моделью составляет −4,99 [−9,06; −1,11] п.п. в no-thinking и −6,84 [−10,91; −2,77] п.п. в thinking. Контроль без тегов тоже потерял IFEval, поэтому по этому опыту нельзя приписать всю просадку тегам.

Плановая разметка дословного текста Qwen в очищенном M2 не дала убедительного преимущества по обычной точности: все десять парных интервалов M2 минус M1 на dev и IFEval включают ноль. На специальном запросе M2 лучше сохраняет содержательную точность, но ставит значительно меньше правильных блоков. Прямой формат M1 даёт 72–93% полных ответов с блоком в ветвящемся протоколе, где декодер добавляет часть тегов Path. При самостоятельной последовательной генерации полных блоков почти нет даже на точном обучающем запросе.

Frozen-наборы дают абсолютную оценку выбранного M1 без выбора по ним: на LIMO 4,47/20,32% верных отдельных ответов в no-thinking/thinking, при 34,5% обрезанных thinking-ответов. Сравнения с исходной моделью или контролем на frozen нет по заданному протоколу.

В основном протоколе целевой навык получен при управляемом ветвлении, а требование минимальной просадки метрик выполнено частично. Цена специального формата особенно заметна на MATH: у M1 17,74% правильных ответов против 40,87% на обычном no-thinking запросе, с подтверждённой содержательной ошибкой в разобранном примере. Последующий пилот показал, что самостоятельная генерация тегов возможна и без их вставки декодером, если при генерации сохранить маску и позиции SFT. Полной dev-оценки такого декодирования ещё нет; содержательная точность MATH остаётся проблемой.
