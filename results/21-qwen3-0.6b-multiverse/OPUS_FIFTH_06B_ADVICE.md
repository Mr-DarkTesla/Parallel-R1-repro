# Советы Opus о следующем SFT для 0.6B

11 октября 2026. Запрос и ответ сохранены в
`audit/opus_fifth_06b_{prompt,response}.json` и
`audit/opus_fifth_06b_response.md`. Вызов через VK AI Proxy стоил
**$0.115884**. С учётом прежнего нижнего предела $75.6307016
известный расход теперь **не менее $75.7465856 из $200**. Первые
транспортные ошибки не имели цены в журнале, поэтому это не точный счёт.

Opus предлагает продолжать **исходную 0.6B с теми же 10 тегами**,
обучать CE только на `<Parallel>…</Parallel>` собственных верных
thinking-текстов Qwen, а вне блока удерживать поведение исходной модели
через KL. Для адаптации предлагает LoRA на attention и обучение строк
тегов, с равным plain-плечом без тегов. Проверять root-tag rank/NLL,
закрытие блока, ответ, полезность путей и IFEval на одинаковом dev.
Forced-start probe назван только диагностикой, не успехом модели.

Это **гипотеза**, не подтверждённый рецепт. В частности:

- утверждение, что CE вне блока вызывает всю потерю точности, ещё не
  проверено причинным сравнением;
- ранние пороги из ответа Opus (`N_pass >= 80`, `>=8/40` полезных,
  `>=31/40` верных) предложены им, а не выведены из данных;
- KL с отдельным parent усложнит память и код; равный plain-контроль
  потребует аккуратно сопоставить позиции после удаления тегов;
- 180 новых M2 уже прошли независимое чтение, поэтому повторный платный
  аудит всех 367 строк без новой причины не нужен;
- ближайшие фактические результаты M1-367 и 4B mixed401 ещё могут
  изменить выбор родителя и частоту предъявления.

Следующий технический шаг: проверить доступные в тренере token loss
weights/LoRA и подготовить CPU-аудит разметки span. Новый SFT запускать
только последовательно после текущей GPU-очереди и с парным plain.
