# Deep51: малый парный набор для SFT

Набор проверяет одну гипотезу после recovery8: может ли небольшой один проход
по более строгим трассам научить содержательному разделению работы, не меняя
обычные правильные ответы. Подготовка не запускает обучение, GPU, pod или
внешний сервис.

## Состав

Оба train-файла содержат ровно 256 разных ID в одинаковом порядке:

| Тип | Строк | Tagged | Plain |
| --- | ---: | --- | --- |
| Принятые Deep51 | 51 | исходный ответ из `accepted51.jsonl` дословно | тот же ответ без контейнера и служебного плана Multiverse |
| `control_th` из recovery8 | 45 | одинаково | одинаково |
| `replay_th` из recovery8 | 160 | одинаково | одинаково |
| Всего | 256 | `sft_deep51_tagged_train.parquet` | `sft_deep51_plain_train.parquet` |

51 Deep51 задачу и 45 control выбирают после исключения пересечений,
детерминированно. Replay включает все 160 строк recovery8. Порядок train
задан seed `deep51-pair-order-20261012`; выбор control задаёт
`deep51-pair-control-20261012`. Списки ID и порядок находятся в
`data/sft_deep51_pair_audit.json`.

Для обеих ветвей используется один и тот же
`data/sft_deep51_pair_val.parquet`: это дословная validation recovery8, 63
строки. Отдельных holdout Deep51 нет, поэтому искусственное разбиение 51
задачи создало бы менее полезный train и не добавило бы независимой проверки.
Общая validation не влияет на целевые train-тексты и делает validation loss
сопоставимым между arms.

## Детерминированное преобразование plain

Tagged-ответ копируется байт в байт из
`audit/deep_trace_round2/accepted51.jsonl`. Plain-ответ строится только для
этих 51 строк:

1. удаляется весь `<Parallel>` контейнер;
2. удаляются `<Goal>`, оба `<Outline>` и `<Conclusion>` вместе с их
   служебным текстом;
3. удаляются только `<Path>` и `</Path>`;
4. два исходных Path-текста остаются дословно и в исходном порядке между
   общим вступлением и общим итогом.

Поэтому plain не получает тегов или маршрутизирующего плана, но не теряет
математический текст путей. Аудит сравнивает нормализованную последовательность
`вступление + Path 1 + Path 2 + суффикс` в обеих ветвях для всех 51 строк.

## Качество и отсутствие утечек

Deep51 создан из `accepted51.jsonl`: независимое ревью приняло 51/51
математически верных и полезных независимых блоков. Аудит пары дополнительно
проверяет для каждого: один нумерованный блок внутри `<think>` в tagged,
два Path, сохранность tagged текста, отсутствие любых тегов в plain,
корректность обоих внешних ответов против `pool.jsonl`, и свидетельство
независимого ревью.

`leakcheck_accepted51.summary.json` подтверждает ноль утечек и ноль
дубликатов/вариантов наших eval для Deep51. Аудит пары проверяет нулевое
пересечение нормализованных вопросов train и shared validation, а также с
фиксированным пилотом из 40 задач. Полный audit пула
`leak_clean_recheck.json` также остаётся нулевым.

## Проверки и длина

Запускать из корня репозитория:

```bash
python3 -B scripts/exp21/prepare_deep51_pair.py
/tmp/exp21-audit-venv/bin/python -B scripts/exp21/audit_deep51_pair.py
```

Второй интерпретатор нужен только для локального `transformers` tokenizer.
Аудит получил 256/256 ID, 51/51 дословных tagged-трасс, 51/51 эквивалентных
plain-решений, 0 тегов вне `<think>`, 0 пересечений с eval и 0 строк длиннее
4096 токенов. Полные результаты: `data/sft_deep51_pair_quality.json`.

## План обучения

Пара предназначена для двух последовательных CPU/GPU-независимых подготовкой
arm с одинаковыми seed, порядком, batch 32 и восемью шагами. Разница целевых
строк есть только у Deep51. Tagged arm использует `parallel_th`; plain arm
использует `control_th`, поэтому Multiverse-маска и отдельный lr тегов
применяются только там, где теги реально присутствуют. До фактического
запуска следует выбрать стартовый checkpoint recovery8 по заранее заданному
правилу и выполнить отдельный run-скрипт.
