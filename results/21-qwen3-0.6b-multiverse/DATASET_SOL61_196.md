# Sol6.1: 196 параллельных траекторий внутри `<think>`

Статус: **принят в парное SFT** 11 октября 2026 года. Файл:
`data/teacher_parallel_accepted196.jsonl`. Сохранены исходные ответы Sol6.1
на 203 разных задачах из очищенного train-пула. Sol видел условие без
эталона; источники и исходные трейсы указаны в каждой строке. Ни GPU, ни
VK AI Proxy при конвертации и ревью не использовались.

| Шаг | Осталось | Причина отсева |
| --- | ---: | --- |
| Сохранённые верные thinking-трейсы | 203 | MATH/GSM8K train, очищенный pool |
| Независимый просмотр всех 203 | 201 | 2 зависимых/повторных пути |
| Явные повторные исключения | 198 | 3 ошибочно пропущенных скринингом |
| Точная группировка, грамматика и `math_verify` | 196 | 2 неоднозначные группировки |
| Личный просмотр полной записи | 20/20 полезных | 0 неверных ответов |
| Независимое слепое ревью | 30/30 полезных | 0 неверных ответов |

Итоговые 196: 72 GSM8K с целым ответом, 29 MATH с целым, 51 MATH с
дробью, 44 MATH с выражением. Каждый исходный reasoning-абзац и внешний
`Final Answer:` сохранены дословно. Конвертер добавляет только
`<Parallel>`, `Goal`/`Outline`, `Path` и `Conclusion` внутри `<think>`;
после удаления добавленной структуры восстанавливается исходная строка.
Проверка `math_verify` проходит 196/196. Ограничение: Outline общие
(`independent computation 1/2`); полезность задают сами пути и объединение.

Утечки: исходные ID принадлежат очищенному `pool.jsonl`; сохранённые
leakcheck-сводки трёх исходных партий показывают ноль совпадений с нашими
eval-наборами и полным MATH test. GSM8K dev исключён при сборке пула.
Проверки и все причины исключений: `audit/teacher_trajectory_candidates.md`,
`audit/teacher_screen_first102.md`, `audit/teacher_screen_last101.md`,
`audit/teacher_parallel_screened_sol61.md`,
`audit/teacher_screened_primary20.md`,
`audit/teacher_screened_independent30.md`.

Парный SFT: `data/sft_teacher_sol61_{tagged,plain}_train.parquet`, 383 строки
на плечо: 196 структурированных позитивов, 45 обычных thinking-контролей,
71 верный собственный ответ Qwen в thinking и 71 в no-thinking. У обоих
плеч совпадают ID, порядок, запросы и фоновые ответы; 63 валидирующие задачи
не пересекаются с train по ID и нормализованному условию. Контроль удаляет
структуру, сохраняя сами тексты Path. Сборка и отчёт:
`scripts/exp21/build_teacher_sft.py`, `data/sft_teacher_sol61_build.json`.
