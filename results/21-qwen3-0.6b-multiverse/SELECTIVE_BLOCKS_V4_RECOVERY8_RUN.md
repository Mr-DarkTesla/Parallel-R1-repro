# Короткое продолжение v4 step56: recovery8

11 октября 2026. Цель: проверить, можно ли вернуть точность ответа
коротким обучением на собственных правильных ответах, сохранив уже
появившиеся полезные блоки v4 step56. Это отдельный поисковый опыт,
не сравнение M1 с M2 при одинаковых 64 шагах.

Стартовая модель: сохранённый BF16 экспорт
`/checkpoints/exp21-m1-selective-v4/step_56/model`. Данные:
[карточка](DATASET_V4_RECOVERY8.md), 256 уникальных train-задач:
46 проверенных `parallel_th`, 50 `control_th`, 160 `replay_th`.
Валидация v4 скопирована дословно, 63 строки. Аудит подтвердил
319/319 ответов, длину до 4096 токенов и отсутствие утечек в
фиксированный пилот и eval-наборы.

Рецепт: один наш H100 на `vcharkin-exp-vm-0`, 8 шагов,
batch 32, microbatch 4, lr `3e-6`, `tag_lr_mult=1`,
`parallel_text_loss_weight=0.1`, маска и позиции Multiverse,
экспорты BF16 после шагов 4 и 8. За 8 шагов модель увидит все
256 строк по одному разу. Предобучающая проверка маски на поде:
14 целей тегов с весом 1, 349 целей текста positive с весом 0,1,
570 replay-целей с весом 1 и 344 control-цели с равномерным весом 0,1.
Равномерный вес control не меняет его градиент, так как loss
нормируется внутри строки.

После завершения v5-прохода на GPU запущено:

```bash
nohup bash /work/parallel-r1/scripts/exp21/run_v4_recovery8_pod.sh \
  > /tmp/exp21-v4-recovery8-launch.log 2>&1 < /dev/null &
```

PID на момент запуска: `17043`. Результаты обучения:
`/tmp/exp21-selective-runs/exp21-v4-recovery8/`.
Обучение завершено, validation loss после шага 8: **0,244859**.
Оба экспорта BF16 проверены и сохранены на нашем постоянном томе:
`/checkpoints/exp21-v4-recovery8/step_4/model` и `step_8/model`.
Маркер `ALL_TWO_STAGED` создан после проверки. Рецепт, порядок строк,
метрики обучения и лог:
[архив](eval_archives/v4_recovery8_train_meta.tgz).

Оценка обоих шагов запущена последовательно на той же GPU:

```bash
EXP21_RUN=/tmp/exp21-selective-runs/exp21-v4-recovery8 \
EXP21_EVAL_ROOT=/tmp/exp21-v4-recovery8-eval \
EXP21_STEPS=4,8 bash /tmp/exp21-eval-v5-checkpoints.sh
```

На момент записи оценка ещё идёт; окончательного решения по модели
нет. Оба экспорта проверяются на тех же 40 masked greedy-задачах.
Затем сравним их с исходной C0, v2 и v4 step56 по верному внешнему
ответу, полным и строго полезным блокам, обрезаниям и длине.
Порог для продолжения: не менее 30/40
верных внешних ответов, 3/40 полезных блоков, не более 2/40
обрезаний и 0 тегов вне `<think>`.

Для следующего парного опыта Deep51 исходный recovery8-чекпоинт
выбирается по числу верных внешних ответов; при равенстве по числу
строго полезных блоков, затем по меньшему числу обрезаний. Выбор
делается только после ручной проверки обоих ответных архивов.
