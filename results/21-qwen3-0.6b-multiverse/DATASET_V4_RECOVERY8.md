# v4 recovery8: набор данных

`data/sft_v4_recovery8_train.parquet` содержит 256 строк и 256 разных задач.
Каждая строка дословно скопирована из train-части v4, включая prompt и ответ:

| kind | задач/строк | состав |
| --- | ---: | --- |
| `parallel_th` | 46 | объединение двух списков ручного ревью v4; `math-train/4669` исключён |
| `control_th` | 50 | все 50 ранее проверенных control-ID v2/v4 |
| `replay_th` | 160 | 80 MATH, 50 GSM8K, 30 ARC |

Повторы одной задачи удалены. Replay выбран детерминированно по SHA-256 от
seed `v4-recovery8-replay-20261012` и ID после исключения positive и control.
Порядок строк задан отдельным seed `v4-recovery8-order-20261012`.

`data/sft_v4_recovery8_val.parquet` является дословной копией validation v4:
63 строки, 21 ID. С train она не пересекается.

## Источники positive

Первые 20 ID взяты из раздела «Ручное чтение» карточки
`DATASET_SELECTIVE_BLOCKS_V4.md`. Ещё 30 взяты из раздела «Независимое
ревью». В списках три повтора: `gsm8k-train/5185`, `gsm8k-train/5854` и
`math-train/4831`. После объединения было 47 ID. `math-train/4669` исключён:
в ревью его блок не засчитан строго полезным из-за лишнего `we can check` в
`<Conclusion>`. Осталось ровно 46 проверенных ID.

## Проверки

`audit_v4_recovery8.py` останавливается при любом нарушении и проверяет:

- точный состав 46/50/160 и 256 разных train-ID;
- повторяемость выбора и порядка;
- полное совпадение каждой train-строки с v4 и validation с v4;
- те же prompts, что у исходных строк и `pool.jsonl`;
- один грамматичный блок с двумя нумерованными Path у каждого positive;
- отсутствие Multiverse-тегов у control/replay;
- правильность внешнего ответа по эталону для всех train и validation строк;
- точную длину после chat template, предел 4 096 токенов;
- принадлежность всех задач очищенному `pool.jsonl` и нулевые результаты
  `audit/leak_clean_recheck.json`;
- нулевое пересечение нормализованных текстов train/validation с 40 задачами
  фиксированного пилота v4 step56.

В архиве пилота есть ложная коллизия сырого ID `gsm8k-train/369`. Train-задача
спрашивает о расходах Monika, eval-задача с тем же локальным номером спрашивает
о времени Walter в зоопарке. Тексты различны. Это следствие независимой
нумерации GSM8K train/dev, описанное в `DATASET_POOL.md`; коллизия целиком
сохранена в audit JSON и не считается утечкой.

Полный отчёт, списки ID и длины:
`data/sft_v4_recovery8_audit.json`.

## Воспроизведение

В окружении проекта с `pandas`, `pyarrow`, `transformers`, `jinja2` и
`math_verify`:

```bash
python3 scripts/exp21/prepare_v4_recovery8.py
python3 scripts/exp21/audit_v4_recovery8.py
```

Набор предназначен для короткого продолжения v4 step56. Изменения trainer в
эту подготовку не входят. Для positive сохраняется уже реализованная схема
весов: теги 1.0, остальной текст 0.1. Отдельный равномерный вес control не
нужен: trainer нормирует loss каждой строки на сумму её маски.
