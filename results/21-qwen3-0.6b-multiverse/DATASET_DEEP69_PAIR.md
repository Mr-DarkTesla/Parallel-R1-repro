# Deep69: парный набор MATH + GSM8K

Набор предназначен для короткой парной абляции без запуска GPU на этапе
подготовки. Он добавляет 18 уже проверенных GSM8K-блоков к 51 принятому
Deep51-блоку MATH, чтобы проверить отсутствие GSM8K-блоков на предыдущем
пилоте.

## Состав

Каждый файл содержит 256 разных задач в одинаковом детерминированном порядке.

| Тип | Строк | MATH | GSM8K | ARC | Thinking |
| --- | ---: | ---: | ---: | ---: | --- |
| Positive | 69 | 51 | 18 | 0 | да |
| `control_th` | 45 | 13 | 10 | 22 | да |
| `replay_th` | 71 | 36 | 22 | 13 | да |
| `replay_nt` | 71 | 36 | 22 | 13 | нет |
| Всего | 256 | 136 | 72 | 48 | оба режима |

Положительные MATH-строки дословно взяты из
`audit/deep_trace_round2/accepted51.jsonl`. У них есть независимое
математическое ревью: 51/51 верный ответ и полезные независимые пути.
Положительные GSM8K-строки взяты из `sft_v4_recovery8_train.parquet`: это
объединение списка ручного чтения и списка независимого ревью v4. Два GSM ID
(`5185`, `5854`) есть в обоих списках; остальные 16 есть в одном из них.

`sft_deep69_tagged_train.parquet` сохраняет 69 исходных положительных ответов
дословно. `sft_deep69_plain_train.parquet` различается только для этих строк:
удалены теги, Goal, Outline и Conclusion, а два содержательных Path остаются в
том же порядке. Остальные 187 строк, включая prompts и ответ, одинаковы.

## Отбор и ограничения

Реплеи выбраны без замены по SHA-256 с отдельными seed для thinking и
no-thinking. Из отбора исключаются все positive и control ID, а также любой
нормализованный повтор текста вопроса. Перед записью набор останавливается,
если пересекается с validation или fixed pilot.

Проверяется очищенный полный pool: в его leak-аудите 0 совпадений с eval, 0
вариантов MATH test и 0 точных совпадений prompts. Для Deep51 повторно
проверяется отдельный leakcheck. Сырой ID `gsm8k-train/369` встречается в
пилоте с другим текстом: train спрашивает о расходах Monika, pilot о времени
Walter в зоопарке. Аудит сравнивает нормализованные тексты и требует их
различия, поэтому это не утечка.

В source-аудите GSM positive имеют 428--617 токенов; Deep51 имеет 521--1201.
Итоговый аудит вычисляет точную длину с Qwen chat template для обеих ветвей и
останавливается при длине больше 4096.

## Важное ограничение сравнения

По сравнению с Deep51-1x одновременно меняются два фактора: появляются
GSM8K positive и добавляется no-thinking replay. Поэтому набор пригоден как
практическая проверка, появляются ли полезные GSM8K-блоки, но не как чистая
причинная оценка только GSM-positive. Для такой оценки нужен отдельный вариант
с теми же 142 `replay_th`.

## Воспроизведение

Из корня репозитория:

```bash
python3 -B scripts/exp21/prepare_deep69_pair.py
/tmp/exp21-audit-venv/bin/python -B scripts/exp21/audit_deep69_pair.py
```

Аудит проверяет 256 строк обеих ветвей: совпадение порядка и prompts,
дословность source-ответов, эквивалентность содержательного решения после
снятия структуры, верность финальных ответов против `pool.jsonl`, структуру
тегов внутри `<think>`, evidence независимости путей, утечки, оба вида replay
и предел 4096 токенов. Результат: `data/sft_deep69_pair_quality.json`.
