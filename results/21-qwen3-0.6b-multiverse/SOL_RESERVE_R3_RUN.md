# Парный SFT с 19 новыми блоками внутри `<think>`

10 октября 2026. После неуспешной генерации собственных структурированных трейсов Qwen проверены новые решения Sol 6.1. [Карточка источника, скрининг и ревью](audit/sol_reserve_round3/README.md). В SFT вошли **только 19** новых примеров, где другой исполнитель проверил всю математику и независимость, а план был вставлен без изменения исходного текста. Ещё 11 размеченных решений исключены до второго независимого ревью, 22 решения не прошли содержательный отбор.

## Сопоставимая смесь

| Источник | Строк |
|---|---:|
| Прежние Sol thinking с внутренними блоками | 187 |
| Подробные Sol thinking из пилота и второй партии | 75 |
| Новые независимо проверенные Sol thinking | 19 |
| Верные собственные Qwen no-thinking | 300 |
| Верные собственные Qwen thinking | 300 |
| Итого | 881 |

Разбиение по ID: 849 train, 32 validation; новые 19 только в train. Для двух плеч одинаковы вопросы, исходные решения, порядок, режим thinking, число строк и validation. Контроль удаляет из целевых ответов только теги, оставляя тот же текст. Подготовка: `scripts/exp21/prepare_deep_aug75_sft.py --new-copies 1 --name sft_sol_deep75_r3 --extra-file results/21-qwen3-0.6b-multiverse/audit/sol_reserve_round3/accepted19.jsonl`; автоматический итог `data/sft_sol_deep75_r3_audit.json`. Токенизатор подготовленной Qwen3 на собственном pod дал новым строкам 363–498 токенов, 0/19 выше лимита 4096. Прежняя сбалансированная смесь уже проверена: максимум 3838, 0 обрезаний до обучения.

Рецепт ровно тот же, что у сбалансированного `deep75`: post-trained Qwen3-0.6B с десятью раздельно инициализированными спецтокенами, `multiverse_structure.py` для независимых путей, `optim.tag_lr_mult=100`, 64 шага, глобальный пакет 32, микро-пакет 4, lr `1e-5`, cosine schedule, длина 4096. Различие в данных: ещё 19 качественных исходных решений по одной копии. Новый lr по frozen не подбирается.

Перед запуском pod `vcharkin-exp-vm-0` проверен по имени и StatefulSet; запрошена одна H100, других наших GPU-процессов на pod не было. Старый скрипт `sft.sh` на pod ещё не поддерживал `RUN_ROOT`, поэтому на **собственный** pod скопирована версия из этой ветки с запуском в `/tmp`; PVC не удалялся и не заполнялся чекпоинтами. `bash -n` и метаданные четырёх parquet проверены: 849/32 строк в каждом плече. В 08:35 МСК запущен один последовательный процесс PID 41671, сначала размеченный вариант, затем контроль. Веса и промежуточные состояния в `/tmp/exp21-r3-runs`, журналы запуска в `/work/exp21/sol_r3`. После обучения метаданные нужно скопировать в репозиторий, а качества оценить на одинаковых dev-запросах обоих плеч; frozen не открывать до выбора лучшего по dev.

Обе модели завершили 64 шага и bf16 экспорт в 08:43:24 МСК. Последняя validation loss: размеченный 0,468819; контроль 0,490430. Это потери на разных целевых строках, их нельзя принимать за сравнение качества ответов. Метаданные обучения, журналы и рецепты без весов сохранены локально в `runs/sol-reserve-r3-train-metadata.tgz` и извлечены в `runs/exp21-sol-reserve-r3{,-control}/`.

Первая попытка оценки закончилась до загрузки модели: оценочный скрипт потребовал чистого git, а в pod была временно скопированная версия `sft.sh`. На собственный pod передан локальный git bundle с уже существующим коммитом `3c39df9`; detached checkout переведён с `d774d24` на этот коммит без изменения экспериментальных данных. После проверки чистого дерева в `scripts` и отсутствия GPU-процесса оценка снова запущена одним процессом PID 42807 в 08:47 МСК. Эта техническая повторная попытка не добавила результатов и не использовала второй GPU.

План оценки: GSM8K, MATH, ARC, MMLU-Pro dev в обычных thinking и no-thinking и на отдельном Multiverse-запросе с блоком внутри `<think>`; IFEval в двух режимах без общей строки `Final Answer:`. Парные 95% интервалы против исходной 0.6B, контроля без тегов и прежнего сбалансированного `deep75`; длина, расчётные форварды и доля обрезания отдельно. Грамматичный внутренний блок должен проверяться отдельно от ответа. Масочный пилот только если полная dev-оценка даёт смысл его проводить. Скрипты запуска: `run_sol_reserve_r3_pod.sh`, `run_sol_reserve_r3_eval_pod.sh`.
