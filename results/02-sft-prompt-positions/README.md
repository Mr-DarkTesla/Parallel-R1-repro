# 02: последовательные позиции промпта в SFT

База: эксперимент 01 (ветка `exp/01-sft-baseline`, отчёт `results/README.md` в ней). Отличие одно:
`ParallelThinkingSFTDataset` строит структурные позиции только для ответа, промпт нумеруется подряд.

## Зачем

Инструкция в промпте содержит теги `<Parallel>`, `<Path>`, `</Path>`, `</Parallel>` как спецтокены. Код авторов разбирает
структуру по всей последовательности и принимает их за параллельный блок: 47 из 239 токенов промпта получали позицию 0,
а позиции ответа сдвигались на 46 относительно инференса, где vLLM нумерует промпт подряд.
Проверка на 30 примерах: после исправления позиции промпта идут 0..P−1, позиции ответа совпадают со старыми
структурными позициями, сдвинутыми на длину промпта, маска внимания не изменилась.

## Выводы

- Модель сама строит параллельные блоки: без роллаута авторов правильных тегов 71–80% при greedy вместо 0%.
  В роллауте авторов доля правильных тегов выросла с 67% до 88%.
- Точность не изменилась: разница в среднем (9.8 против 10.4) меньше шума наборов AIME/AMC из 30–40 задач.
- Исправление оставляем, следующий эксперимент строится поверх 02.
- При temperature 1.0 структура заметно хуже, чем при greedy (36–39% против 71–80%): модель 0.6B при полном сэмплировании
  часто сбивается с формата.
